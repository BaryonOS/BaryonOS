# Kernel rules
Read the root AGENTS.md and ARCHITECTURE.md and SECURITY-AND-QUANTUM.md under docs/.
Use Rust no_std; every unsafe block requires a local SAFETY justification covering validity, aliasing, alignment and lifetime. A comment alone proves nothing: subject it to counterexamples and review.
Describe ownership of frames/page tables, exception and syscall ABIs, interrupt state and lock ordering. Validate user pointers and lengths. Never retain references to unmanaged guest/userspace memory across rescheduling without a valid model.
Capabilities are process-bound, kernel-validated handles with rights and validity. Integers/pointers must not confer unrestricted authority. Test privilege escalation, stale handles, exhaustion and revocation.
Keep the kernel small. No GUI, network parser, cryptographic protocol or storage policy in privileged code without an explicit ADR. The single-core prerequisites for SMP have been demonstrated (accepted K02–K05/K07); K06 is accepted only within the source-bound QEMU scope in docs/verification/K06-ACCEPTANCE.md. Future SMP work must preserve the single-core regression gates and must not claim physical-hardware acceptance.
Commands: build only with `python3 -B tools/build.py --kernel-feature <feature>` (`--help` lists profiles); smoke with `python3 -B tools/run.py --smoke --milestone <m1..m5>`. Each subsystem's native gate is the workflow job that builds its feature; list it with `python3 -B tools/agent_gate.py --job <workflow>.yml#<job> --list`. Host tests of the shared logic: `cargo +1.90.0 test --locked -p kernel-core`.
