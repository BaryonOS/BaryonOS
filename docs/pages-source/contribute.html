Choose the kind of contribution

Baryon OS welcomes bounded, evidence-oriented contributions. A useful contribution can improve a confusing explanation, describe a reproducible defect, test an accessibility assumption or implement one agreed system step.

Ask, discuss or improve the product direction

Use GitHub Discussions for questions, product ideas and accessibility feedback. Describe the task, the confusing behavior and the outcome that would help. Search for an existing topic first so related evidence stays together.

Report a defect or documentation problem

Use the issue forms for a reproducible defect, documentation correction or bounded implementation proposal. Include the exact source version, environment, steps, observed result and expected result. Do not present host or simulated behavior as native OS evidence.

Propose code

Read the contribution guide, current project state and the contracts for the subsystem before editing. Keep one owner per write set, preserve unrelated work and state which checks ran. Pull requests remain drafts until their source-bound checks and required reviews are complete.

Start with a small interface. The project is broad, but a reviewable change should have one goal, one invariant, an exact write set, acceptance commands and an explicit evidence limit.

Report a security problem privately

Send exploitable details through GitHub Private Vulnerability Reporting. Do not place vulnerability details, secrets or real user data in a public issue, discussion, pull request or test log.

Check licensing before reuse

Project-owned software listed in the file register is offered under MPL-2.0. Documentation, third-party components and Baryon OS names and marks are not automatically covered by that software license.
