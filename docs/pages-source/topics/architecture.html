How do the pieces fit together?

The first development target is x86_64 in a QEMU virtual machine with UEFI firmware. This simplified path helps explain the layers; it does not mean that every planned service or app is integrated.

  1. UEFI firmwareOVMF provides the boot interface inside the virtual machine.
  2. Project loaderThe Baryon OS loader prepares the kernel and passes boot information to it.
  3. KernelThe independently developed Rust kernel manages privileged resources and process boundaries.
  4. Processes and servicesIsolated components perform bounded jobs through defined interfaces.
  5. SDK, apps and UIApplication-facing interfaces and the desktop sit above those boundaries; their integration remains in progress.

What makes the kernel independent?

The native system does not use Linux, BSD, XNU or another existing OS kernel as its foundation. Development tools, UEFI firmware, public standards and reviewed libraries can still be used. A Linux development computer does not turn the guest OS into a Linux distribution.

How are permissions meant to cross layers?

A capability is a kernel-checked right to a particular resource and operation. The design calls for bounded requests between processes: selecting one document for an app should not grant access to every file. The privacy and security chapter explains the intended limits; the progress chapter separates implemented paths from full release acceptance.
