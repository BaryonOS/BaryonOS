What does the roadmap measure?

The public roadmap has 100 fixed, weighted acceptance points. A criterion earns its points only when it is fully accepted with the evidence it requires. Partial implementation receives no partial points. The score is not elapsed time, a security rating or a release forecast.

What exists today?

The repository contains a native boot chain, kernel, process and capability infrastructure, services, drivers, an SDK and native UI work. Integration and acceptance differ across components. The current project record identifies what was implemented, what was tested and what remains open; the existence of a directory or a passing build does not establish a complete OS.

What evidence counts?

Host tests check selected code on a development OS. QEMU tests check a recorded native guest configuration. Physical hardware tests apply to the exact tested devices; human review covers its stated scope. These levels are distinct. A simulation, green CI job or second AI review cannot substitute for a required native, hardware or human check.

Is it ready for daily use?

No. There is no supported production release. The full native test release, physical hardware acceptance and maintenance path remain open. Read the QEMU exploration route if a bounded development build is useful.
