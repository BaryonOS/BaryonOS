What should ordinary use eventually include?

The full product assignment covers first start, sign-in, a familiar desktop, settings, search, windows, documents, recovery and accessibility. It also requires useful applications for browsing, text, images, PDF, media, calculations, screenshots, diagnostics and productivity tasks. The aim is a coherent product rather than a collection of technical demonstrations.

How should apps and data work together?

Applications are intended to be replaceable tools. Opening one document should grant access to that selected material, not to every file. Installation, provenance, network access, personal-data access and administrative actions are separate decisions. Supported formats, failure states and import/export behavior must be tested before compatibility is claimed.

What connected functions are planned?

Internet access, name resolution, authenticated transport and per-app destination permissions are product requirements. Optional storage can use an explicitly paired personal or family NAS, or a deliberately selected external provider that receives opaque client-encrypted objects rather than content keys. Authorized devices should resume synchronization while preserving conflict and recovery behavior.

What reliability and maintenance are required?

A daily-use release requires safe installation, system and app updates, rollback, accessible recovery, repeated cold starts, extended combined workloads, supported hardware, reproducible release artifacts and a maintenance policy. The release matrix includes normal paths and failures; individual accepted subsystems do not substitute for this integrated evidence.
