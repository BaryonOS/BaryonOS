Is Baryon OS Linux?

No. The native system does not use the Linux, BSD, XNU, Windows or Android kernel as its foundation. Linux may be used as a development host, and public standards, firmware interfaces, emulators and reviewed libraries may be used without changing the guest kernel's identity.

Can it be installed on a personal computer?

No supported installer or hardware profile is available. The documented route is an isolated QEMU virtual machine with disposable images. Do not attach a host disk or treat a development image as a daily-use system.

What works today?

Selected boot, kernel, process, capability, storage, networking, UI, SDK and research paths have implementation and evidence. Integration varies. Use Status and the source-bound records rather than inferring readiness from folders, screenshots or test totals.

Does local-first mean offline only?

No. Normal internet access and continuity are requirements. Local-first means that local work remains possible and remote storage or synchronization is explicit, bounded and not a silent vendor fallback.

Will existing Windows, macOS or Linux apps run?

No general compatibility promise exists. Baryon OS has its own SDK and application model. Controlled ports and maintained engines may be investigated, but format support, permissions, performance and failure behavior require separate acceptance.

Is the project proven secure or quantum-proof?

No. The project defines security requirements and investigates post-quantum protection, but claims remain limited to their recorded tests and review scope. A quantum simulator is not a physical QPU or proof of speedup.

What license and support apply?

Project-owned software in the file register uses MPL-2.0; other material retains its applicable terms. There is no production support commitment. Security reports follow the private route in the repository security policy.
