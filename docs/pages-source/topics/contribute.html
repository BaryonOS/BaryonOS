How can a non-coder help?

Use Discussions for questions, product ideas and accessibility feedback. Describe the task, the confusing behaviour and the outcome that would help. Search for an existing topic first.

Where do defect reports and code changes belong?

Use Issues for a reproducible defect, a documentation correction or a bounded implementation task. Before proposing code, read the contribution guide, the relevant architecture and security contracts, and the development and test instructions. A pull request should identify its changed scope, executed checks and remaining limits. The architecture guide and development route offer starting points.

How should a security problem be reported?

Send exploitable details through GitHub Private Vulnerability Reporting, which the repository security policy identifies as its private route. Do not place them in a public issue, discussion, pull request or log, and do not include secrets or real user data. There is no guaranteed response time or production security support.

What licensing scope applies?

Project-owned software listed in the file register is offered under MPL-2.0. Documentation, third-party assets and Baryon OS names and marks are not automatically covered by that software licence. Check the applicable terms before reusing material.
