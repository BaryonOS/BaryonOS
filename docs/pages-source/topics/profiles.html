What should first start look like?

The design calls for a recognisable local setup: language, keyboard, optional network, a local account, recovery material, optional PIN, storage choice and a short tour. A vendor account is not mandatory. An interrupted setup must not leave a half-created identity or keys.

How are local users separated?

The intended model distinguishes administrator, standard and temporary guest roles. Each user needs a separate namespace and keys. An administrator may manage accounts and reclaim local space but must not gain a function that decrypts another user's content. Password and administrator secrets belong only in trusted system surfaces.

How does accessibility fit the design?

Accessibility is part of the product identity rather than a separate theme. Keyboard use, readable scaling, contrast, reduced motion, assistive technology and alternative input are baseline requirements. Additional visual, motion, typography and stimulus preferences should combine without turning off essential safety or information.

What is implemented?

Native session and UI components exist, but the complete first-start, authentication, multi-user key separation and native accessibility acceptance remain open. Browser prototypes can test interaction ideas; they do not demonstrate kernel enforcement or assistive behavior in the native OS.
