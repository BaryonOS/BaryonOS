What does installing an app authorize?

Installation should authorize no general access by itself. Package provenance, permission to install, permission to launch, access to selected material, network destinations and administrative actions are separate decisions. A signed package can establish origin and integrity under a selected key; it cannot establish that the app is safe.

How should an app reach personal data?

The intended route uses explicit task grants. A document picker or other trusted portal grants a bounded handle for the selected object and operation. Helpers and extensions must not inherit broader rights or bypass revocation. Removing an app is not permission to erase user documents.

Where can apps come from?

The package design allows multiple explicitly chosen sources. Source rotation or revocation can stop new verification without silently deleting already installed apps. A production installer still needs durable source authority, native storage integration, transactional recovery, user-facing consent and a complete launch boundary.

What application ecosystem exists now?

The repository contains an SDK, example applications and package-verification and app-management cores. A publicly documented SDK criterion is accepted. Native installation, update/removal, broad everyday application coverage and integrated per-task permissions remain open.
