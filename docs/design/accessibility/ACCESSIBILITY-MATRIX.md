# BaryonOS accessibility matrix (UX-A11Y-R)

Date: 15 November 2026 (Europe/Amsterdam). Research and matrix only: no design-system, prototype or implementation file was changed; integration into ds-1.x is task UX-A11Y-DS.
Companion text: `ACCESSIBILITY-RESEARCH.md` (method, Q1-Q6 per need, axes, conflicts, contract extensions, user tests, limitations).
Structural check: `python3 -I docs/verification/a11y-research-20261115/check.py .` from the repository root.

Value sets. Tier: baseline (every regular theme, no configuration, never optional) or setting (an independently combinable axis). Empirical evidence grades the effect of the adaptation on the fixed scale strong, moderate, limited, insufficient, contradicted; a normative clause is never counted as empirical proof, and AI review is never evidence of user effect. Prototype status refers to `ui/design/system/`. Native status names the component or the contract to extend. 'new contract: <name> (none exists yet)' marks a contract that does not exist in the repository yet (research section 10.2). Safety rows: every row whose Adaptation starts with 'Safety:' is a safety limit; it is baseline by rule, holds under every theme, setting combination and toggle, is never a setting, and check.py fails when a required safety limit has no tagged row or a tagged row is not baseline. Safety rows are the dangerous-effect limits plus keyboard-filter safety, consent under alternative input and security signals; the other Q6 limits (for example speech never the only input, never sound-only, no keyboard trap, no data loss on time-out, notifications never take focus) are mandatory access limits: baseline rows, not tagged, held by the rule that Tier is baseline exactly when the Axis cell starts with 'none (baseline)'. Grades follow the basis rule of research section 1.3 (rule 5), and contradicted follows rule 6: a row is limited or above only when a cited source tests the adaptation or recognised-organisation consensus recommends it; 'Evidence caveat' in the Verification method cell states the basis where it is not obvious. A Native status cell that covers parts with different status names each part after the leading status. Repair history and the traceability map (dossier row ids, standard hashes, cited clauses) are in research Appendix A; the build and repair scripts are local, uncommitted artefacts.
