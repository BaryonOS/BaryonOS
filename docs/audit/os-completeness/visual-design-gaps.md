# Visueel ontwerp en interactie

## Wat bestaat

Materiaal is gekozen na conceptvergelijking. De productspecificatie beschrijft
content-first objectcontinuïteit, verwisselbare gereedschappen, geschiedenis,
capabilitybewuste toegang en een rustige eigen visuele taal. Een browserprototype
bevat meerdere schermen en responsive toestanden. Native compositor-/Materiaal
code is aanwezig in ontwikkelbranches die nu op main zijn geïntegreerd of als
historische rapporten opgeslagen.

## Wat ontbreekt aan bewijs

- Geen volledige native first-boot → desktop → settings → app → recovery-flow
  die op één release-image is bediend.
- Geen volledige interactie-/statusmatrix: loading, empty, error, cancel,
  retry, stale responses, focus, selection, long text en 200% scale.
- Geen complete native multi-window, monitor, fractional scaling, HDR,
  rotation en compositor-crash ervaring.
- Geen onafhankelijke menselijke beoordeling van originaliteit, herkenbaarheid
  zonder branding, acht-uurscomfort, cognitieve belasting en gebruikerswaarde.
- Geen native font shaping, toegankelijkheidssemantiek en reduced-motion
  bewijs over alle apps.

Materiaal is een inhoudelijk ontwerpconcept, niet bewezen “beter” of uniek.
Kleuren, blur, hoeken en animaties alleen leveren geen futuristische of
onderscheidende productarchitectuur op. Screenshots ondersteunen, maar
vervangen geen bediening.
