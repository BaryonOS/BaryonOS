# Core crate rules
Read the root instructions. These crates are shared by the kernel, drivers, services and SDK: a change also requires the tests of its consumers (CODEX-WORKFLOW.md section 2). Keep crates `no_std`-capable and host-testable, and keep existing `#![forbid(unsafe_code)]` attributes.
Root-workspace members (`boot-protocol`, `elf-loader-core`, `kernel-core`, `smp-lock`, `capability-core`, `driver-core`, `pci-core`, `virtio-core`, `ui-core`, `update-core`, `app-package-core`, `artifact-store-core`): `cargo +1.90.0 test --locked -p <crate>`, `cargo +1.90.0 clippy --locked -p <crate> --all-targets -- -D warnings` and `cargo +1.90.0 fmt --all -- --check`. `app-package-core` and `artifact-store-core` also have their own workflows (`app-management-quality.yml`, `artifact-store-quality.yml`).
`capability-core` and `update-core` carry security policy: test denial, stale or revoked authority and wrong signers, and run the native gate of the consumer (`signed-updates.yml` for update policy).
Standalone crates with their own `Cargo.lock` (`system-journal`, `power-lifecycle-core`, `background-job-core`, `notification-core`, `firmware-descriptor-core`) have no CI gate. Run the same commands with `--manifest-path crates/<crate>/Cargo.toml` and report the result as a local check, not as gate evidence.
